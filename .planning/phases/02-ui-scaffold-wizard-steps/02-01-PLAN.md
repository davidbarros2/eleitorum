<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → worker thread | UI thread sets cancel flag; worker thread reads it via `threading.Event` |
| worker thread → core pipeline | Worker passes a bound `_progress_cb`; pipeline calls it inside `run_pipeline` |
| pipeline → UI thread | Worker emits Qt `Signal` objects; Qt queues delivery to the main thread |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01-01 | Tampering | `pyproject.toml` PySide6 install (supply chain) | mitigate | Pin exact version `PySide6==6.11.1`; researcher slopcheck verdict `[OK]` (see 02-RESEARCH.md Package Legitimacy Audit); no `[ASSUMED]`/`[SUS]` packages require gating in this plan |
| T-02-01-02 | Information Disclosure | `PipelineWorker.error.emit(str)` | mitigate | Emit ONLY `str(exc)` — never `traceback.format_exc()`. Code-level enforcement; ASVS V7 |
| T-02-01-03 | Denial of Service | Worker thread blocked / cannot cancel | mitigate | `threading.Event` checked in `_progress_cb` every 100 rows; `PipelineCancelledError` is NOT `EleitorumError` so it bypasses pipeline's swallow-and-return path |
| T-02-01-04 | Tampering | Cross-thread signal delivery races | accept | Qt queued connections are thread-safe by design (Qt event loop guarantees); no shared mutable state beyond `threading.Event` |
| T-02-01-SC | Tampering | pip install of pytest-qt | mitigate | slopcheck `[OK]` per 02-RESEARCH.md; ~10 yr package age; no gate required |
</threat_model>
