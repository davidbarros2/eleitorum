From src/eleitorum/ui/worker.py (verified during planning):
- class PipelineWorker(QThread): __init__(source, output_type, output_path, parent=None)
- Signals (NOTE the routing — this is load-bearing):
    * progress = Signal(int, int)        # (current_row, total_rows)
    * finished = Signal(object)          # PipelineResult; emitted for BOTH success AND validation failure
    * error    = Signal(str)             # PT-PT message; ONLY for unexpected exceptions (ImportError, MemoryError, ...)
    * cancelled = Signal()               # only after cancel() + PipelineCancelledError raised by _progress_cb
- Lifecycle: call worker.start() (NOT worker.run()) — QThread.start() launches a separate thread and the queued signals reach the test via qtbot.waitSignal.
- Cleanup: call worker.wait() AFTER waitSignal returns (avoids Windows QThread-still-alive teardown warnings).

- Validation failures are caught internally and returned as PipelineResult(success=False) — they DO NOT raise out of run_pipeline.
