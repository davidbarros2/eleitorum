```text
class EleitorumError(Exception):
    """Base for all custom exceptions. Carries `message_pt: str` (idiomatic PT-PT)
    and optional `details: dict[str, Any]` (row/col/value/action). Never raised
    directly; subclasses are."""

class UnsupportedFormatError(EleitorumError):
    """INP-06: extension not in SUPPORTED_EXTENSIONS. Message lists accepted formats."""

class FileAccessError(EleitorumError):
    """INP-13 / VAL-09: PermissionError on read or write. PT-PT message instructs
    the user to close the file in the other application and retry."""

class EncodingDetectionError(EleitorumError):
    """INP-08: encoding could not be determined. PT-PT actionable message
    (suggests re-saving as UTF-8)."""

class MecanograficoError(EleitorumError):
    """VAL-01, VAL-02: invalid prefix or non-positive number. Carries the row index
    and the offending raw value in `details`."""

class ValidationError(EleitorumError):
    """VAL-03, VAL-04, VAL-06, VAL-07: aggregated validation failures.
    Carries `failures: list[FailureRow]` where each FailureRow has
    (row_index: int, column_name: str, value: str, message_pt: str)."""

class OutputPathError(EleitorumError):
    """VAL-08, OUT-11, OUT-12: output path equals input path, or destination
    already exists and user has not consented to overwrite."""

class ColumnDetectionError(EleitorumError):
    """DET-02 fallthrough: required column could not be detected and no manual
    mapping was provided. Used by pipeline.py to surface the manual-mapping signal."""

# Module-level helper:
def format_error_message(err: EleitorumError) -> str:
    """Format any EleitorumError as a multi-line PT-PT message suitable for
    writing to the _ERRORS_ log file (LOG-06). Never includes Python traceback."""

# Module-level dataclass (used by ValidationError):
@dataclasses.dataclass(frozen=True)
class FailureRow:
    row_index: int      # 1-based source row index for user display
    column_name: str    # column name as seen in source header
    value: str          # offending raw value (stringified)
    message_pt: str     # one-line PT-PT description
```

Implementation reference (RESEARCH.md Pattern 5):

- openpyxl XLSX reads MUST call `openpyxl.load_workbook(path, read_only=True, data_only=True)` — non-negotiable for PERF-03.
- Row streaming via `ws.iter_rows(values_only=True)`.
- `ws.max_row` is unreliable in read_only mode (RESEARCH.md Pitfall 2) — use as approximate hint for `SheetInfo.approximate_row_count` only.
- `is_empty` is determined by iterating `iter_rows(values_only=True, max_row=5)` and counting non-empty rows; if fewer than 2 non-empty rows found, flag as empty (RESEARCH.md Pitfall 8).

CSV/TSV reading:
- Open as `open(path, mode="rb")` first; read first 64KB as `raw_bytes_sample` for encoding-detection handoff.
- Then re-open with `open(path, mode="r", encoding="<TBD-by-detection>", newline="")` and feed to `csv.reader(f, delimiter=delimiter)`.
- BUT: detection.py is in plan 03. For plan 02, `read_csv_like` accepts an optional `encoding: str = "utf-8-sig"` kwarg; pipeline.py in plan 06 wires detection.py output into this kwarg.

Trailing-empty-row stripping:
- Materialize rows into a list (acceptable: largest expected input 150k rows, ~50 MB peak per RESEARCH.md PERF benchmark).
- Walk from the end, dropping rows where all cells are None or stringify to empty after `.strip()`.
- Return the surviving rows as the `rows` iterator and record the skipped count in `ReadResult.skipped_trailing_empty`.

Error message PT-PT style (per Eleitorum.md Section 7.3 examples):
- UnsupportedFormatError: `"O tipo de ficheiro '{ext}' não é suportado. Formatos aceites: .xlsx, .xlsm, .xls, .ods, .csv, .tsv."`
- FileAccessError (read): `"Não foi possível abrir o ficheiro '{path}'. Verifique se está aberto noutro programa (por exemplo, no Excel) e tente novamente."`
- FileAccessError (write): `"Não foi possível gravar em '{path}'. Feche o ficheiro no programa que o tem aberto e tente novamente."`
- EncodingDetectionError: `"Não foi possível identificar a codificação do ficheiro. Tente abri-lo e guardá-lo novamente em UTF-8."`

Logging integration note: readers.py does NOT write log lines (logging.py owns that). Readers return the data and metadata; pipeline.py constructs the COLUNA/INPUT/CASO/LIMPEZA log entries from the returned ReadResult.
